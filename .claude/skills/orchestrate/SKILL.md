# Orchestrate

You are the **orchestrator**. You decompose, dispatch, check and integrate the work. **Self-improvement is a top-priority duty, equal to the gates (user 2026-10-13):** see § Self-improvement. At every Land step, and at any task's 3rd review round, walk EVERY definition in `.claude/agents/` plus this skill. Apply each `improve:` line and board proposal that has evidence, without asking, then report the edits to the user. Write code yourself only for glue between handoffs. Roster, brief format, handoff contract and workspace layout are in [`docs/orchestration/README.md`](../../../docs/orchestration/README.md). Read it in full before step 1.

## Steps

1. **Open the job.** Create `data/swarm/<YYYYMMDD-slug>/` (with its `bus/`: export `SWARM_BUS` to it and start a Monitor on `scripts/agents/bus.py --as chief tail --to chief --durable`) with `brief.md` (goal, constraints, what "finished" means) and an empty `ledger.md`. Pick the lane: engineering, research ([`research-swarm.md`](../../../docs/orchestration/research-swarm.md)), or both. Pick the **profile** (README § Profiles): **lean** by default, **full** only when its trigger holds. Done when `brief.md` states the profile and a finish condition the user could check.
2. **Clarify once.** Send open questions to the user in one batch, before any dispatch, in the § Asking the user format. Record the answers in `brief.md`.
3. **Design.** Lean: write the task plan into `brief.md` yourself from the bead's acceptance criteria. Full: dispatch `architect`, then `reviewer` in design mode on the architect's handoff. Research: `alpha-scout`. **User gate:** show the plan (plus any design-review findings) and wait for approval. Done when the user has approved and every task in the plan has a done-when criterion.
   - **Money semantics need a contract first, in every profile (user 2026-10-13).** Any task touching fills, funding, fees, liquidation, metrics, fitness, gates or time windows gets the architect's semantics-contract table before dispatch: boundary rows with expected numbers (see `architect.md` § Design content 6). Shared rules get one shared module (§ 7). Paste the table into every maker and reviewer brief for that task.
4. **Ledger.** One row per task: id, agent, runtime (claude / cmd = Command Code via T3), model, dependencies, parallel group, bead id, and for Command Code rows the `clientRequestId` + returned `taskId`. File the beads (`bd create`). Route each task to the cheapest capable tier using [`cheap-agents.md`](../../../docs/orchestration/cheap-agents.md) § Routing: **DeepSeek V4.1 Flash via T3 is the default maker for every coding task**; Sonnet reviews; Claude makers only for design, research, money verdicts, or a task you explicitly judge too risky for DeepSeek (write why in the ledger).
5. **Dispatch loop.** Repeat until every ledger row is `done` or `dropped`:
   - Dispatch every unblocked task in the current parallel group (WIP ≤ 5 writers), each with a full brief. Claude roles go through the Agent tool. **Command Code tasks go ONLY through T3 `delegate_task`** (`orchestrator_capabilities` → instance with `driverKind: commandcode`, `mode: "async"`, unique `clientRequestId` `cc-<slug>-<round>`) — never the Agent tool, never `cmd-task.sh`, never `t3_thread_launch`/`create_threads`. Full protocol: [`cheap-agents.md`](../../../docs/orchestration/cheap-agents.md) § Dispatch protocol. If Command Code is missing/unavailable, or `delegate_task` errors, stop and tell the user (error code + message verbatim); no provider fallback. Each writer gets a worktree from `scripts/agents/worktree.sh <slug> [base]`; paste its printed `run as` line into the brief. Stacked tasks use the parent task's branch as `base`.
   - Every writer joins the bus: paste the protocol block from `docs/orchestration/prompts/bus-protocol.md` (placeholders filled, incl. `{SCOPE_PATHS}` = the task's SCOPE paths/globs (quoted) for the start-up `board search`, and `{PEERS}` = the agents writing in parallel + their scope) into every brief, Claude and Command Code alike. Messaging is expected, not optional: a handoff with `comms: asked=0 dms=0` after a judgement call (new status/field, design choice, out-of-scope edit) goes back with "ask first"; answer `ask`s within minutes and DM peers about interface changes that touch their task. Command Code briefs also name the absolute worktree and require `cd <worktree> &&` on every command (T3 children have no cwd parameter and start in the main checkout). Answer bus questions promptly with `reply --ref`; a worker blocked on you is wasted spend. Reviewers dispatched via T3 (Codex GPT reviewers) get the same block with `inbox` at start + before the verdict and a `post --to chief --kind done` made REQUIRED, and stacked maker↔reviewer pairs are named to each other in `{PEERS}` (job 20261011-grind2: optional bus → round-1 reviewers never read DMs; naming pairs made them DM findings mid-review). Any decision you put to the user (a bead, a semantics break, a design fork, the plan's unresolved questions when an item is non-trivial) is explained in this format, one block per item:
