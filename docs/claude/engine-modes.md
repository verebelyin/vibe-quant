# Engine modes: screening, validation, liquidation, sizing

Read before changing screening/validation fill or cost behaviour, liquidation, position sizing, the margin limit, or their launch parameters. Moved verbatim from CLAUDE.md (2026-10-17); SPEC.md stays authoritative.

One engine (NautilusTrader), two modes:
- **Screening** (also used by discovery): simplified fills, multiprocessing; models leverage + funding (archive; holes charged a flagged fallback rate); starting balance = `parameters.initial_balance` (default 1000) on screening launches (discovery stays 1000). Liquidation is an opt-in per-run overlay (OFF by default; `off|isolated|cross`, leverage a whole number in [1,125], default 10); the screening venue runs at `parameters.leverage` in every mode and, when the overlay is on, every metric is recomputed from the truncated ledgers. Each strategy queues orders in a per-instrument outbox released on its own two synthetic 1m fill ticks per bar; open positions are marked at run end; drawdown is marked on strategy-timeframe bars. Position size per trade = min(risk_per_trade / stop, max_position_pct cap per symbol) of equity; both run-level, defaults 0.02 / 0.5 ([SPEC.md § Position sizing](SPEC.md#position-sizing)). A run-level **margin limit** (`max_margin_pct`, OFF when absent; launch form **Max margin in use (% of equity)**, paper default 50%) refuses an entry whose margin in use (open + pending + new) would exceed that fraction of equity, at the run leverage in backtests and the venue-verified per-symbol leverage in paper/live.
- **Validation**: custom FillModel; orders release on the instrument's own next 1m detail bar (the latency preset only selects the fill model on bar data); full cost modeling. Clamps the window to 1m coverage (`notes.data_window`) and fails without 1m data.
- **Liquidation** (opt-in, OFF by default): a per-run overlay for screening, validation and discovery; `liquidation_mode` `off|isolated|cross` with leverage a whole number in [1,125] (default 10; shared rule `vibe_quant/liquidation_settings.py`). Screening/validation set the top-level `liquidation_mode` on the launch (API/UI; the launch form has a **Liquidation** Off/Isolated/Cross select that reuses the existing **Leverage** input; leverage = `parameters.leverage`, the screening venue's leverage in every mode); discovery uses `--liquidation-mode isolated --leverage 20` (deprecated `--liquidation-leverage` alias), or API `liquidation_mode`+`leverage` (deprecated `liquidation_leverage` alias; a conflict is a 422; its launch form has an always-visible **Leverage (1-125)** input); promote/replay inherit the parent; a mode-on run's results show a liquidation chip and counts. Needs MARK 1m klines (`python -m vibe_quant.data download-mark --start YYYY-MM-DD`). Details: [SPEC.md § How to turn liquidation on](SPEC.md#how-to-turn-liquidation-on).
