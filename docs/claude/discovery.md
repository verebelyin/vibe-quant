# Discovery pipeline

Read before running or interpreting discovery, or changing discovery, fitness or gates. History: [`../discovery-journal.md`](../discovery-journal.md).

## Current behaviour
- Discovery and screening share one code path (`NTScreeningRunner` → `StrategyCompiler`). A champion replays exactly within one run when `eval_windows=1`.
- **Liquidation is an opt-in overlay, OFF by default.** Settings and flags: [`engine-modes.md`](engine-modes.md). No penalty term or gate: mode on scores liquidation-adjusted metrics (same formula, from truncated ledgers). Rows carry `notes.liquidation = {mode, leverage}` plus `liquidation_count` / `liquidation_forfeited`; mode off writes no `liquidation*` key. Peak RSS ≈ 1.15 GB/worker with it on (size `max_workers`); off is unchanged.
- **Fail closed on liquidation data:** a missing or incomplete MARK 1m series, an unpriceable open survivor, or a fill/funding/cash flow at run end fails the run with `LiquidationIntegrityError: liquidation_mode='isolated': ...` (never a `-999`/`-inf` row), at every stage (train, holdout, cross-window, WFA, full-range).
- **`path_divergence`:** set when there is at least one hit: NT's later positions were sized on pre-liquidation equity and missed re-entries cannot be rebuilt.
- **Liquidation exit timing (screening/discovery, mode on, timeframe above 1m):** a resting STOP_MARKET/LIMIT exit is timed at the first 1m LAST bar inside the strategy bar (after it went live) that reached its level (stop: touch; limit: trade through). MEASURED, strategy 239 BTCUSDT 4h: screening vs validation hits 0 vs 0 at 50x, 60 vs 60 at 125x.
- **Position sizing is a run-level setting, never a gene.** CLI `--max-position-pct` / `--risk-per-trade` (API top-level `max_position_pct` / `risk_per_trade`), defaults 0.5 / 0.02, stored only when non-default. Recorded in `notes.sizing`; promote/replay inherit it (unreadable `notes.sizing` is a 409). A sweep key naming a sizing field (including dotted spellings) is rejected.
- **Margin limit and bankroll grid are opt-in, OFF by default.**
  - Margin limit: `--max-margin-pct` (API `max_margin_pct`, in (0, 1]) caps margin in use (open + pending + candidate entry) via `vibe_quant/margin_limit.py`; in `notes.sizing`, inherited by promote/replay.
  - Bankroll grid: CLI `--bankroll-modes` (`isolated`/`cross`) + `--bankroll-leverages` (whole 1–125) + `--bankroll-max-margin-pcts` (in (0, 1]), all three, or API `bankroll_grid = {modes, leverages, max_margin_pcts}`. Cells = product(modes in `(isolated, cross)` order, sorted leverages, sorted cushions), deduplicated, at most 12. Exclusive with run-level `--liquidation-mode` / `--leverage` / `--max-margin-pct`.
  - Discovery picks strategy and cell together; every cell × seed evaluation is a DSR trial (**N = Σ over cells × seeds**).
  - A champion records `top_strategies[i].bankroll = {liquidation_mode, leverage, max_margin_pct}`. Promote/replay inherit the cell (missing or invalid is a 422).
- **`--indicator-pool` also bounds MA genes:** an MA name in an explicit pool enables it, else none drawn (`None` = all).
- **Tiny runs produce no rows:** fitness scores 0 below 50 trades or at return <= 0 (`fitness.py:573`): a pop 8–12, 2-generation, 2–3 month run ends `no_viable_strategies` with no rows. Prove row-level behaviour with a pipeline test.
- **Fitness** = 35% Sharpe + 25% (1 − MaxDD) + 20% PF + 20% Return; 0 below 50 trades.
- **`eval_windows` (default 3) stores WORST-of-N sub-window metrics** (min Sharpe/return/PF, max DD; each window needs ≥ max(1, min_trades // (2N)) trades). A full-window replay legitimately differs.

## Gates
- **Fail closed:** 0 champions + `guardrail_rejections`. Every run keeps a default 20% holdout, used once as the final gate.
- **Bootstrap-CI floor** (statistic = t-stat mean/std·√n): 1m 0.5, 4h/1d 0.0 (1.0 is unpassable at ~50–180 trades/yr). A champion flagged `no_bootstrap_ci=true` is overfit (forced-past ones collapsed in validation: 5.40 → −2.78).
- **DSR N is the effective count:** this run's EV-matched effective trials (`notes.dsr_trials.run_n_eff`; raw when < 2 retained series) + earlier same-timeframe overlapping-train runs' summed `run_n_eff` under `n_rule` `cumulative_effective_same_tf_overlapping_train` (`gate_n/prior_n/prior_run_ids`; `prior_legacy_*` tallied, not charged). DB error -> run-only N plus `prior_error`; `--no-dsr` records `run_n_eff` = raw. DSR passes at the legacy PSR statistic >= the run's q95 MC spread (default; `--dsr-rule emax` = 1.6449) and tests the champion's **mark-to-market** series; missing fails DSR closed.
- **Buy-and-hold gate (fail closed):** champions must beat the directional equal-weight, daily-rebalanced buy-and-hold Sharpe of their symbols over the train window, on the MTM daily series (`notes.buy_hold_gate`). `symbol_agg=worst` also checks each symbol against its own benchmark. Skips only for a non-NT backtest fn; `--no-buy-hold-gate` disables.
- **Consistency:** `validation/consistency.py` flags screening→validation collapse (holdout champions compare on holdout metrics).
- **Seed:** `--seed N` (auto-drawn otherwise, stored in `notes.seed`) replays a run exactly with the same config and code.
- **Fails loudly:** an all-errored eval batch raises `DiscoveryEvaluationError` (run `failed`, not "0 champions").

## Data and speed facts
- `compiler_version_hash()` changes with indicator/codegen changes: `bd recall discovery:compiler-hash`. Champion rankings: `bd recall discovery:champions`.
- **HYPE history is short:** ~504 d (2025-05-30 10:30 → 2026-10-16: ~403 d train, ~101 d holdout, ~134 d/window at `eval_windows=3`; `OWN_TREND(200)` NaN for ~200 daily bars). Multi-symbol runs must start >= 2025-05-31, shortening every symbol's window (else fill-tick coverage fails closed); HYPE-only champions are low-confidence. HYPE funds every 4h; one archived skip (2026-06-24 04:00) is a flagged fallback (`0.00005 x notional`) in `funding_fallback_settlements`.
- **1m is slow:** Rust-native indicators (SMA/EMA/CCI/STOCH/ATR) are ~10× faster than pandas-path ones (ADX/MACD/BBANDS/KAMA).
